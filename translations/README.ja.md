# Reader's Ear

[English](../README.md) · **日本語** · [简体中文](README.zh-Hans.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md)

Reader's Earは、AIエージェントが書いたり推敲したりする文章を、想定読者にとって自然に読めるものにする[Agent Skill](https://agentskills.io)です。言語やジャンルは問いません。避けるべき語の一覧ではなく、作業の進め方をエージェントに示します。Claude（Claude Code、claude.ai、Claude Desktop、Cowork）のほか、Codex、Cursor、Gemini CLI、GitHub Copilotなどのエージェントにもインストールできます。

## ルールではなく進め方を示す理由

文章からAIらしさを消す、いわゆる「humanizer」系のスキルには、ルールに基づくものが多くあります。ここでいうルールとは、AIが書いたように感じられる語や言い回しの一覧です。ルールには次のような難点があります。

- たいていは一つの言語向けに書かれていて、ほかの言語には通用しません。
- 用途によっては逆効果になります。たとえば、契約書やビジネスメールに欠かせない言い回しまで禁じてしまうことがあります。
- モデルがどれほど進歩しても、出力の質はルールの出来を超えられません。

モデルはすでにどの言語でも文章の良し悪しを見分けられる、というのがReader's Earの前提です。足りないのはルールではなく、進め方です。そこでこのスキルは、どの言語でも通用する進め方だけを示し、判断はモデルに任せます。モデルが進歩すれば、そのぶん結果も良くなります。

## 動作の概要

指示の全文は[`SKILL.md`](../plugin/skills/readers-ear/SKILL.md)にあります（日本語の参考訳は[SKILL.ja.md](SKILL.ja.md)）。要点は次のとおりです。

- **執筆**：エージェントは新しい文章を書くとき、まず誰が読むのか、その読者が何をすでに知っていて、何のために読むのかを見極めます。そのうえで、最初の下書きからその読者に向けて書きます。書き終えたら読者の立場で一度読み、見つけた問題を直します。
- **推敲**：文章を想定読者の立場で読み、具体的な問題だけを直します。一語から文章全体の構成まで、どこにある問題も対象です。元の文章の事実、主張、語り口は保ち、良い文章はほぼそのまま返します。依頼の範囲を超える問題や事実の誤りは直さず、指摘として伝えます。
- **見落としやすい問題**：執筆でも推敲でも、特に二つの問題に注意します。一つは、ほかの言語の語順や日付の書き方などが持ち込まれることです。もう一つは、エージェントとユーザーの会話や、作業中にエージェントが付けた呼び名など、読者が見ていない文脈に頼った書き方です。
- **入念モード**：外からの視点を取り入れて、時間をかけて念入りに書いたり推敲したりするモードです。時間もトークンも通常よりかなり多く使うため、頼まれたときだけ使われます。エージェントは自分で文章を評価する前に、新しく起動した二つのAIインスタンス（サブエージェントなど）に手伝ってもらいます。一方は対象の文章を見ずに、同じジャンルの参考になる文章を集めます。もう一方は、予備知識なしに対象の文章を読みます。エージェントは二つの報告を踏まえ、重要な言い回しや事実を、翻訳された資料ではなく、もともと対象の文章と同じ言語で書かれた資料で確かめてから直します。最後に、参照した資料と、省いた手順を伝えます。
- **適用範囲**：既定では、ユーザー以外の人が読む文章と、ユーザーへの報告に、頼まれなくても自動で使われます。報告とは、依頼に取り組んだあとの最終的な回答と、ユーザーが読むためにエージェントが作る資料のことです。対象を、エージェントが書くすべての文章に広げることも、ユーザー以外の人が読む文章だけに絞ることもできます（「使い方」を参照）。

## 安全性

Reader's Earの中身は指示文だけです。スクリプト、フック、MCPサーバーは含みません。エージェントがこのスキルに従って書き込むのは、作業対象の文章のほかには、適用範囲の選択を記録する一文だけです。ユーザーが適用範囲を選んだり変えたりしたとき、または適用範囲についての質問に答えなかったときは、エージェントがその一文を個人用の指示ファイル（ユーザーレベルの`CLAUDE.md`など）かアカウントのメモリに保存し、保存先を伝えます。

入念モードでは、エージェントはさらに、サブエージェントなどのAIインスタンスを新たに起動します。また、参考になる文章や、Webページなどの資料を検索して読みます。検索には用語、固有名詞、短い語句を使い、ユーザーの文章の一節をそのまま検索語にすることはありません。

## インストール

claude.aiとClaude Codeの両方を使う場合は、先に次の点を確かめてください。Claude Codeは、クラウドセッションでは、claude.aiアカウントに登録されたスキルを読み込みます。ターミナルでも、バージョン2.1.273以降で、そのアカウントに`/login`でサインインしていれば読み込みます。この条件に当てはまる使い方なら、ZIPアップロードだけで済みます。プラグインもインストールすると、Claude Codeは同じスキルを二重に読み込んでしまいます。

それ以外の場合は、エージェントを使う環境に合わせて、インストール方法を選んでください。

| 使う環境 | 推奨する方法 |
| --- | --- |
| ローカル環境のClaude Code | [Claude Codeプラグイン](#claude-codeプラグイン) |
| claude.ai、Claude Desktop、Cowork、Claude Code on the web | [claude.aiアカウントへのZIPアップロード](#claudeaiclaude-desktopcowork) |
| Codex、Cursor、Gemini CLI、GitHub Copilotなどのエージェント | [`npx skills`](#ほかのエージェント) |

なお、以下の手順に出てくるメニューやボタンの名前は、英語UIでの表示名です。

### Claude Codeプラグイン

Claude Codeのセッションで、次のコマンドを実行してください。

```
/plugin marketplace add motestream/readers-ear
/plugin install readers-ear@readers-ear
```

1行目のコマンドで、このリポジトリをプラグインのマーケットプレイスとして追加します。2行目で、そのマーケットプレイスからプラグイン`readers-ear`をインストールします。`readers-ear@readers-ear`は`@`の前がプラグイン名、後ろがマーケットプレイス名で、どちらも`readers-ear`です。

Claude Code 2.1.275以降では、次のコマンド一つで両方を実行できます。

```
/plugin install readers-ear --marketplace motestream/readers-ear
```

**更新**：`/plugin marketplace update readers-ear`を実行してください。`/plugin`の「Marketplaces」で、このマーケットプレイスの自動更新をオンにすることもできます。

**チームで共有する**：ターミナルで、プロジェクトのリポジトリのルートに移動して、次のコマンドを実行してください。

```sh
claude plugin marketplace add motestream/readers-ear --scope project
```

続いて、このコマンドが書き込んだ`.claude/settings.json`をコミットしてください。チームメンバーがこのプロジェクトでClaude Codeを使うと、プロジェクトフォルダーを信頼するかどうかを尋ねられます。承認したメンバーにはこのマーケットプレイスが追加され、各自がそこからプラグインをインストールできます。

**クラウドセッション**（Claude Code on the web）では、ローカル環境にインストールしたプラグインは読み込まれません。クラウドセッションで使うには、代わりにスキルをclaude.aiにアップロードしてください。または、このリポジトリ（クローンしたものか、ダウンロードして展開したZIP）の`plugin/skills/readers-ear`フォルダーを、プロジェクトの`.claude/skills/`にフォルダーごとコピーし（`.claude/skills/readers-ear/SKILL.md`となる形）、コミットしてください。

### claude.ai、Claude Desktop、Cowork

1. コード実行がオンになっていることを確認してください。スキルの利用にはコード実行が必要です。この設定は、Free、Pro、Maxプランでは「Settings > Capabilities」にあります。Teamプランでは、コード実行とスキルは組織単位で最初からオンになっています。Enterpriseプランでは、オーナーが「Organization settings > Plugins & skills」の「Policy」タブで、両方がオンになっていることを確かめます。
2. GitHubで「Code > Download ZIP」を選んでこのリポジトリをZIPファイルでダウンロードし、展開してください。
3. `plugin/skills/readers-ear`フォルダーを圧縮して、新しいZIPファイルを作ってください。ZIPファイルの中に`readers-ear`フォルダーがあり、その中に`SKILL.md`が入っている形にします。フォルダー名は`readers-ear`から変えないでください。
4. claude.aiで「Customize > Skills」を開き、「+」をクリックしてください。続いて「Create skill > Upload a skill」を選び、作成したZIPファイルを指定してください。

これでスキルがアカウントに登録され、Claude DesktopとCoworkでも使えるようになります。Claude Codeでも、「[インストール](#インストール)」の冒頭で述べた条件で読み込まれます。Enterpriseの組織のオーナーは、スキルをアップロードして全メンバーに一括で提供することもできます。

**更新**：「Customize > Skills」で古いバージョンを削除してから、新しいZIPファイルをアップロードしてください。

### ほかのエージェント

この方法にはNode.jsが必要です。次のコマンドを実行してください。

```sh
npx skills add motestream/readers-ear -g
```

`-g`を付けると、スキルはユーザー単位（すべてのプロジェクトで共通）でインストールされます。付けない場合は、現在のプロジェクトにだけインストールされます。実行すると、インストール済みのエージェントが検出され、どれにインストールするかを尋ねられます。エージェントをあらかじめ指定するには、`-a codex`のように`-a`を付けてください。

**更新**：`npx skills update`を実行してください。

**GitHub CLI 2.90以降**では、プレビュー版の`gh skill`でもインストールできます。

```sh
gh skill install motestream/readers-ear readers-ear --scope user
```

インストール先のエージェントを尋ねられます。`--agent`で指定することもできます。この方法でインストールした場合は、`gh skill update`で更新できます。

**手動インストール**：このリポジトリ（クローンしたものか、ダウンロードして展開したZIP）の`plugin/skills/readers-ear`フォルダーを、エージェントのスキル用ディレクトリにフォルダーごとコピーしてください。たとえばClaude Codeでは、`~/.claude/skills/readers-ear/SKILL.md`となるように置きます。

## 使い方

Reader's Earは、エージェントがユーザー以外の人に向けて文章を書くときと、ユーザーに報告するときに自動で働きます。「この文章を自然にして」のように、普段の言葉で頼むこともできます。名前で呼び出すには`/readers-ear`を使います（Claude Codeプラグインとしてインストールした場合は`/readers-ear:readers-ear`）。

**入念モード**：はっきり頼んだときだけ使われます。「時間をかけて念入りに推敲して」「時間をかけて念入りに書いて」のように頼んでください。いつも入念モードにしたい場合は、`CLAUDE.md`などの指示ファイルにそう書いておくこともできます。

**変更の範囲を絞る**：「誤字だけ直して」のように伝えてください。範囲外の問題は、エージェントが直さずに指摘します。

**適用範囲**：既定の対象は、ユーザー以外の人が読む文章と、ユーザーへの報告です。報告には、ファイルを読む、コマンドを実行するといった作業をして答えた依頼への最終的な回答と、ユーザーが読むためにエージェントが作る資料が含まれます。最終的な回答に至るまでの作業中にエージェントが書くことや、会話の内容だけで返せる短い返事は対象外です。対話しながら使っていて、設定を保存できる環境では、エージェントは既定の対象に入る文章を初めて渡したあと、既定のままにするか、すべての文章に広げるか、ユーザー以外の人が読む文章だけに絞るかを一度だけ尋ねます。答えなかった場合は既定のままとし、そのことを保存して、以後は尋ねません。後から変えたいときは、エージェントに頼んでください。設定を保存できない環境では、この質問はしません。そうした環境で範囲を変えたいと頼んだ場合、変更は現在の会話にだけ適用され、指示ファイルなどに書き加えるための一文が示されます。それを書き加えておけば、以降のセッションにも反映されます。

## 試してみる

本格的に使う前に、次のことを試してください。

- 同じモデルで、スキルを使った場合と使わない場合の出力を比べてください。できれば複数の言語で試し、ビジネスメール、契約条項、UIの文言など、定型表現のあるジャンルも含めてください。
- メモを渡して、ほかの人が読む文章を書くよう頼んでください。追加で直しを頼まなくても、読者にとって読みやすい文章が返ってくるはずです。
- すでによく書けている文章を渡して、推敲を頼んでください。ほとんど変わらずに戻ってくるはずです。
- 事実は正確でも、順序がわかりにくい文章を渡して推敲を頼んでください。事実はそのままに、構成が組み替えられて返ってくるはずです。
- コーディング作業中に、エージェントが書くコミットメッセージ、PRの説明文、ドキュメントが良くなっているかを確かめてください。あわせて、ほかの人が書いた既存の文章に手を付けていないかも確かめてください。
- 何段階かある作業を頼み、終わったあとの最終的な回答を確かめてください。作業中にエージェントが付けた呼び名ではなく、ユーザーが知っている言葉で書かれていて、必要以上に長くないはずです。

## コントリビューション

- `SKILL.md`または英語版の[README](../README.md)を変更したときは、対応する翻訳も同じコミットで更新してください。その際、スキルの指示の翻訳ファイル（`SKILL.<言語コード>.md`）冒頭にある日付も更新してください。
- `SKILL.md`の変更は、少なくとも三つの言語でテストしてください。そのうち一つは、学習データの少ない言語にしてください。プロジェクトが対応するモデルそれぞれでもテストしてください。あわせて、非対話モードでの実行（`claude -p`）とクラウドセッションで、適用範囲を尋ねる質問と、その回答の保存がどう動作するかも確認してください。
